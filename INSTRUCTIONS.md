# Инструкция по эксплуатации бота-модератора

## Что делает бот

Бот следит за разделами (темами) супергруппы. Для каждого раздела ты сам
решаешь, какие типы контента разрешены — можно разрешить только фото,
только видео, фото+видео+ссылки, вообще ничего кроме конкретного эмодзи,
или включить "ультра"-режим, где писать может только админ. Всё это
настраивается командами прямо в чате, без правки кода.

Есть предохранитель: пока не введёшь `/start`, бот вообще ничего не
удаляет, даже в зарегистрированных разделах.

Разделы и пресеты привязаны к конкретной группе (если бот когда-нибудь
окажется больше чем в одной группе — они не смешаются между группами).
Чёрный список слов и настройки антифлуда пока общие на весь бот сразу,
для всех групп, куда он добавлен, — если это станет проблемой при
нескольких группах, тоже можно будет разнести по группам отдельно.

---

## Типы контента

| Тип | Что это |
|---|---|
| `photo` | Фото |
| `video` | Видео |
| `gif` | Анимация/гифка |
| `text` | Обычный текст (без ссылки) |
| `link` | Сообщение содержит ссылку (обычную или гиперссылку в тексте) |
| `sticker` | Стикер (любой) |
| `voice` | Голосовое сообщение |
| `document` | Файл/документ |
| `dice` | Анимированный эмодзи: 🎰 🎲 🎯 🏀 ⚽ 🎳 |

Подпись (caption) к фото/видео не считается отдельным "text" — она едет
вместе с медиа и не мешает, если медиа разрешено.

## Команды

### Глобальные (в любом месте группы)

| Команда | Кто может | Что делает |
|---|---|---|
| `/start` | Админ | В группе: включает модерацию во всех зарегистрированных разделах. В личке с ботом: присылает эту инструкцию |
| `/stop` | Админ | Полностью выключает модерацию (предохранитель) |
| `/status` | Любой | Внутри раздела — показывает его настройки. Вне раздела — общий статус |
| `/sections` | Любой | Список всех зарегистрированных разделов и их правил |
| `/types` | Любой | Список всех доступных типов контента |
| `/инструкция` (или `/instructions`, `/help`, `/помощь`) | Любой | Присылает эту инструкцию — работает в любом чате: в группе, в конкретной теме или в личке с ботом |

### Настройка раздела

Эти команды можно писать **внутри самого раздела** (тогда название в
конце указывать не нужно — бот и так поймёт, о каком разделе речь) —
**или из любой другой темы** (например из отдельной служебной темы
"Модерация"), указав название раздела последним аргументом.

| Команда | Кто может | Что делает |
|---|---|---|
| `/register <название>` | Админ | Регистрирует **текущий** раздел под модерацию (только изнутри самого раздела — иначе бот не узнает его id) |
| `/unregister [раздел]` | Админ | Снимает раздел с модерации, удаляет его настройки |
| `/section_on [раздел]` | Админ | Включает модерацию раздела |
| `/section_off [раздел]` | Админ | Выключает модерацию раздела |
| `/allow <тип> [раздел]` | Админ | Разрешает тип контента (например `/allow text Мемы`) |
| `/deny <тип> [раздел]` | Админ | Запрещает тип контента |
| `/adminonly_on [раздел]` | Админ | Ультра-режим: писать может только админ |
| `/adminonly_off [раздел]` | Админ | Выключает ультра-режим |
| `/allow_dice <эмодзи> [раздел]` | Админ | Разрешает конкретный dice-эмодзи (например `/allow_dice 🎰 Слоты`) |
| `/deny_dice <эмодзи> [раздел]` | Админ | Убирает эмодзи из списка разрешённых |

### Мьют отдельных пользователей

Действует **на всю группу сразу**, во всех разделах (даже незарегистрированных) —
это не настройка раздела, а бан конкретного человека на уровне всей группы.

| Команда | Кто может | Что делает |
|---|---|---|
| `/mute` (ответом на сообщение) | Админ | Мьютит автора сообщения бессрочно |
| `/mute 2` (ответом на сообщение) | Админ | Мьютит автора на 2 минуты — временный, снимается сам |
| `/mute @username` | Админ | Мьютит по юзернейму бессрочно (если он публичный) |
| `/mute @username 2` | Админ | Мьютит по юзернейму на 2 минуты |
| `/mute <user_id>` | Админ | Мьютит по числовому ID (можно тоже с числом минут последним аргументом) |
| `/unmute` (аналогично /mute, без длительности) | Админ | Снимает мьют |
| `/muted` | Любой | Список всех замьюченных: с пометкой источника (от админа / флуд / решение ИИ) и сколько осталось, если мьют временный |

Длительность — всегда **последним числом** в аргументах команды; без
числа мьют бессрочный (до ручного `/unmute`). Замьюченному человеку
удаляются вообще все его сообщения, в любом разделе, пока мьют
действует. Админа замьютить нельзя. Самый надёжный способ указать
пользователя — **ответить командой на его сообщение** (юзернейм
резолвится через Telegram и работает не всегда, например если у человека
нет публичного @username — но у бота есть и собственная база
username→id, см. ниже в разделе про ИИ).

### Чёрный список слов

Один общий список на весь бот. В отличие от остальной модерации, работает
**во всей группе сразу, в любом разделе** — даже незарегистрированном через
`/register`. Достаточно, чтобы была включена глобальная модерация (`/start`).
Проверяется и обычный текст, и подпись к фото/видео.

| Команда | Кто может | Что делает |
|---|---|---|
| `/blacklist_add <слово>` | Админ | Добавляет слово в чёрный список |
| `/blacklist_remove <слово>` | Админ | Убирает слово из чёрного списка |
| `/blacklist` | Любой | Показывает весь текущий список |

При срабатывании бот удаляет сообщение и пишет в тот же раздел:
*"Сообщение удалено. Причина: запрещённое слово «слово»"*.

### Антифлуд

Общий на весь бот (как мьют и чёрный список — работает в любом разделе,
зарегистрирован он или нет). **Админов не касается вообще.**

Логика: срабатывает от любого из трёх признаков —
1. Слишком много сообщений подряд за короткое время
2. 3+ одинаковых сообщения подряд (например, спам одним и тем же текстом)
3. 3+ сообщения подряд с упоминанием одного и того же `@username`

1-е и 2-е срабатывание — предупреждение (сообщение удаляется, в чат пишется
"предупреждение X/3"). 3-е — автоматический мут на настраиваемое время.
**После мута счётчик предупреждений обнуляется** — следующее нарушение
снова начинается с первого предупреждения, а не с мгновенного мута.
Мут временный и снимается сам по истечении времени.

| Команда | Кто может | Что делает |
|---|---|---|
| `/flood_on` | Админ | Включает антифлуд |
| `/flood_off` | Админ | Выключает антифлуд |
| `/flood_mute_time <минуты>` | Админ | Задаёт длительность мута после N-го предупреждения |
| `/flood_warn_count <число>` | Админ | Задаёт, сколько предупреждений даётся перед мутом (по умолчанию 3) |
| `/flood_status` | Любой | Показывает текущие настройки антифлуда |
| `/flood_reset` (ответом на сообщение или `@username`/id) | Админ | Сбрасывает счётчик предупреждений пользователю |

### Пресеты сценариев

Именованный снимок всех настроек модерации разом: какие разделы
зарегистрированы и что в них разрешено, чёрный список слов, настройки
антифлуда и включена ли модерация в принципе. Сохранил один раз —
дальше применяется одной командой вместо повторного набора всех команд
настройки. Хранится в том же Redis, что и текущие настройки — переживает
рестарт сервиса на Render сам по себе, никаких дополнительных действий
после рестарта не нужно.

| Команда | Кто может | Что делает |
|---|---|---|
| `/preset_save <название>` | Админ | Сохраняет текущие настройки под этим именем |
| `/preset_load <название>` | Админ | Заменяет текущие настройки на сохранённые в пресете |
| `/presets` | Любой | Показывает список сохранённых пресетов |
| `/preset_delete <название>` | Админ | Удаляет пресет |
| `/migrate_presets` | Админ | Разовая техническая команда: переносит пресеты, сохранённые старой версией бота (до того, как разделы и пресеты привязали к конкретному чату), в текущий чат. Если `/presets` вдруг показывает пусто, хотя раньше что-то сохранял — сначала попробуй эту команду |

Пресеты (как и сами разделы) привязаны к конкретному чату — если бот
когда-нибудь окажется в нескольких группах, пресеты одной группы не
будут видны и не будут применяться в другой.

Пример: настроил разделы и антифлуд под обычный день →
`/preset_save обычный`. Для вечеринки временно ослабил правила →
настроил заново → `/preset_save вечеринка`. Переключение между ними
одной командой: `/preset_load обычный` или `/preset_load вечеринка`.

### ИИ-разговор через упоминание

Если написать в чате `@имя_бота <вопрос>`, бот отправит текст после
упоминания в ИИ (Groq) и ответит прямо в тот же чат/раздел. Не
завязано на модерацию — работает независимо от того, включена она
(`/start`) или нет.

Нужен ключ `GROQ_API_KEY` в переменных окружения (`.env` локально,
Environment на Render). Без ключа бот ответит, что ИИ не настроен,
вместо того чтобы падать.

**Отвечает по факту, не выдумывает.** Если вопрос похож на "какие
разделы есть", "что разрешено в Мемах", "какой статус у раздела X" —
боту в промпт подмешиваются РЕАЛЬНЫЕ данные из настроек этого чата
(список всех разделов или настройки конкретного), и ИИ отвечает строго
по ним, а не сочиняет правдоподобный на вид, но не соответствующий
реальности ответ. Разделы других групп, куда бот тоже мог быть добавлен,
она не видит и не путает с этим чатом.

**Характер (по умолчанию):** отвечает от лица властной женщины-админа
с большим стажем модерации — строго, уверенно, без заискивания.

| Команда | Кто может | Что делает |
|---|---|---|
| `/ai_persona <описание>` | Админ | Меняет характер, которым отвечает ИИ |
| `/ai_persona_show` | Любой | Показывает текущее описание характера |

**Право на мьют:** у ИИ есть два повода написать в конце ответа скрытую
команду вида `/mute @username 3` (1–5 минут) — бот её вылавливает и
вырезает из текста перед отправкой, в чате её не видно:

1. **Самозащита.** Если автор сообщения ей грубит или ведёт себя
   неуважительно — может замьютить именно его, полностью на своё усмотрение.
2. **Просьба админа.** Если написавший — админ группы и явно просит
   замьютить кого-то другого (например `@имя_бота замьють @spammer за
   спам на 2 минуты`) — ИИ выполнит просьбу и замьютит именно того, кого
   попросили, а не автора сообщения.

Какой из двух случаев сработает, решает не юзернейм в тексте, а то, кто
реально прислал сообщение (`message.from_user` — подделать нельзя):
не-админ может попросить ИИ замьютить только самого себя. Если не-админ
пытается попросить замьютить кого-то другого, бот прямо отвечает в чат:
*"у тебя не хватает авторитета, чтобы просить о таком"* — и мьют не
выполняется.

Администраторов ИИ замьютить не может ни при каком раскладе — это
проверяется кодом отдельно, а не доверяется самой модели.

Юзернейм для мьюта резолвится через собственную базу бота (пополняется
из каждого сообщения, увиденного в группе), а не через Telegram — так
находит по нику почти всегда, даже если у человека не было личной
переписки с ботом. Если человек ещё ни разу не писал в группе после
последнего обновления бота, резолв может не сработать — тогда надёжнее
ответить (reply) на его сообщение обычной командой `/mute`.

Отменяется той же командой `/unmute`, что и обычный мьют, — по типу
источника мьюта разницы нет.

**Право на размут** — по той же схеме, зеркально мьюту:

1. **Прощение по усмотрению ИИ.** Если пишет тот же человек, которого
   замьютили, и извиняется/просит войти в положение — ИИ может сама
   решить простить и снять мут именно с него, а может и отказать.
2. **Просьба админа.** Если пишет админ и явно просит снять мут с
   конкретного `@username` — ИИ выполняет, указывая именно того, кого
   попросили.

Не-админ, который просит размутить **кого-то другого** (не себя), получает
тот же отказ про недостаток авторитета, что и при попытке замутить чужого
через ИИ. Если человек, которого просят простить, на самом деле не в
муте — ИИ так и ответит, а не наврёт про несуществующее прощение.

**Прощение опирается на историю, а не только на текущую просьбу.** Бот
хранит последние 15 сообщений каждого не-админа в каждом чате (журнал в
Redis, старые сообщения сами вытесняются новыми). Если пишет замьюченный
и просит амнистию, ИИ получает эту историю вместе с его сообщением и
реально её учитывает: если там правда есть спам, оскорбления, реклама
или другое явное нарушение — отказывает и коротко объясняет, что смущает.
Если ничего подозрительного не находит — прощает и сама добавляет в ответ,
что мут, возможно, был ошибкой или перестраховкой админа.

**Извинения не действуют на мьют, выданный лично админом.** Если замьютил
именно живой админ через `/mute`, ИИ откажет в самопрощении сразу, не
разбирая историю сообщений и не принимая никакие оправдания — снять
такой мут может только сам админ. Это же касается мьютов, наложенных
**по просьбе админа через саму ИИ** (случай "явная просьба админа" выше) —
такой мьют считается решением админа, а не ИИ, и извинениями от самого
пользователя тоже не снимается. Ограничение касается только
самопрощения (когда замьюченный просит за себя); если админ сам просит
ИИ размутить кого-то третьего — это по-прежнему проходит, независимо от
того, кто выдал тот мут изначально. Мьюты от антифлуда и от самой ИИ
(самозащита за грубость, когда сработала именно она без просьбы админа)
извинениями снимаются как раньше.

Если админ грубит ИИ и она решает замьютить его саму (или кого-то просит
замьютить, а цель оказывается админом) — ИИ прямо отвечает, что у
человека админ-права и она не может это выполнить, вместо того чтобы
полагаться на собственную формулировку отказа.

**Остальные команды по просьбе админа.** Кроме мьюта/размута, ИИ может
по прямой просьбе админа (только админа — рядовому участнику откажет
с той же фразой про недостаток авторитета) выполнить и другие действия
бота прямо из разговора, без явного набора команды руками:

- разрешить/запретить тип контента в разделе (`/allow`, `/deny`)
- включить/выключить раздел (`/section_on`, `/section_off`)
- добавить/убрать слово из чёрного списка (`/blacklist_add`, `/blacklist_remove`)
- включить/выключить антифлуд (`/flood_on`, `/flood_off`)
- включить/выключить модерацию целиком (`/start`, `/stop`)

Например: `@имя_бота выключи текст в разделе Мемы` или `@имя_бота добавь
слово реклама в чёрный список`. Если раздел не назвать явно — действие
применится к тому разделу/теме, где идёт разговор. Как и с мьютом, ИИ
сначала реально выполняет действие и только потом отвечает — если
что-то пошло не так (раздел не найден, неизвестный тип контента), она
честно напишет, что именно не получилось, а не соврёт об успехе.

### Табель нарушителей

Копится накопительно и автоматически: каждое удаление за чёрный список
слов, несовпадение типа контента, флуд, писанину в разделе "только
админ", а также каждый мьют (ручной, за флуд, от ИИ или по просьбе
админа через ИИ) добавляет очко нарушителю. Хранится в том же Redis,
что и всё остальное, отдельно от списка замьюченных — переживает
рестарт и не сбрасывается сама по себе.

| Команда | Кто может | Что делает |
|---|---|---|
| `/violators [раздел]` | Любой | Публикует таблицу под заголовком "ТАБЕЛЬ ОБСИРАЕМОСТИ!" — топ-20 по числу нарушений с последней причиной у каждого. Без аргумента — в текущую тему, с названием раздела — туда (раздел должен быть зарегистрирован через `/register`, как и у команд `/allow`/`/deny`) |
| `/violators_reset [цель]` | Админ | Без аргумента — обнуляет весь табель. С `@username`/id/reply на сообщение — сбрасывает счёт только этому человеку |

### Служебные

| Команда | Что делает |
|---|---|
| `/id` | Показывает thread_id текущего раздела |
| `/ids` | Ответом (reply) на сообщение со стикером — его file_unique_id |
| `/whatis` | Ответом (reply) на любое сообщение показывает, какими типами контента бот его считает (фото/видео/текст/ссылка и т.д.) — удобно для диагностики, почему `/allow`/`/deny` не сработал так, как ожидалось |

## Примеры настройки

**Мемы — только фото, видео и ссылки:**
```
/register Мемы
/allow photo
/allow video
/allow link
```

**Слоты — только конкретный эмодзи 🎰:**
```
/register Слоты
/allow_dice 🎰
```

**Гартик — только фото и гифки:**
```
/register Гартик
/allow photo
/allow gif
```

**Чат — не регистрировать вообще**, тогда бот его не тронет в принципе
(даже без отдельной команды "не трогать" — незарегистрированные разделы
бот не проверяет).

**Раздел, где может писать только админ (объявления и т.п.):**
```
/register Объявления
/adminonly_on
```

**Удалённое управление из отдельной темы "Модерация":**
Зарегистрировать раздел всё равно нужно изнутри него самого (один раз),
а вот дальше настраивать можно из специально созданной темы, например
"Модерация", просто дописывая название раздела в конце команды:
```
/allow text Мемы
/deny video Гартик
/adminonly_on Объявления
/section_off Слоты
```
Удобно, когда не хочется заходить в каждый раздел по отдельности, а все
настройки держать в одном месте.

**Мьют на конкретное время (снимется сам):**
```
/mute @spammer 5
```
или ответом на его сообщение: `/mute 5`. Без числа — мьют бессрочный.

**Чёрный список слов (работает сразу во всех разделах):**
```
/blacklist_add реклама
/blacklist_add спам
/blacklist
```

**Попросить ИИ замьютить спамера (только для админа, без команды `/mute`):**
```
@имя_бота замьють пользователя @spammer за спам на 2 минуты
```
Если попросит не админ — ИИ откажет и ответит, что у него не хватает
авторитета, чтобы просить о таком.

**Попросить прощения у ИИ после мута (сработает не всегда — решает сама):**
```
@имя_бота прости, я больше не буду, сними мут пожалуйста
```

**Как выглядит амнистия целиком, шаг за шагом:**
1. Кто-то флудит или грубит → получает мьют (от антифлуда, от ИИ-самозащиты или вручную от админа)
2. Замьюченный пишет боту, упоминая его: `@имя_бота извини, погорячился, отпусти`
3. Бот подтягивает его последние 15 сообщений из истории и решает:
   - если мьют выдал **живой админ** — сразу жёсткий отказ ("снять может только он"), история даже не разбирается
   - если мьют от **антифлуда** или **ИИ-самозащиты** — ИИ смотрит историю: нашла реальный спам/оскорбления → отказывает и коротко объясняет что смущает; ничего криминального не нашла → прощает и сама пишет в ответе, что мут мог быть перестраховкой
4. Если простила — мут снимается в тот же момент, никаких дополнительных команд вводить не надо

**Попросить ИИ снять мут с другого человека (только для админа):**
```
@имя_бота размуть @spammer, он всё понял
```

**Посмотреть табель нарушителей:**
```
/violators
```
или отправить его сразу в конкретный раздел, даже если пишешь из другой темы:
```
/violators Чат
```

---

`/stop` — глобально выключает модерацию во всех разделах сразу, не
трогая сами настройки (разделы, типы, ультра-режим). При следующем
`/start` всё вернётся как было.

## Как проверить текущие настройки

- `/status` внутри раздела — покажет именно его правила
- `/sections` — общий список всех разделов сразу
